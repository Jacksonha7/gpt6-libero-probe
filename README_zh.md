# 通用多模态模型操作机器人时，瓶颈在哪里？

[English](README.md) | **中文**

这是一个在 LIBERO 仿真里做的可复现实验，用来区分通用多模态模型在操作机械臂时能做到什么、做不到什么。当前的研究对象是 GPT-6（`gpt-6-astra`，通过 Codex CLI 调用）；实验框架适用于任何能接收图像、返回结构化文本的模型。

📄 [完整报告](docs/report_zh.md) · 🎬 [全部视频案例](docs/cases_zh.md) · 🛠 [复现](code/README_zh.md) · 📊 [原始成功次数](results/success_rates.csv)

## 研究问题

多模态模型控制机械臂时，限制它的是哪一步：决定做什么、判断东西在空间里的位置，还是生成电机指令？

我们把它拆成三个更具体的问题来回答。每个问题都有一个真值基线：用物体真实位置驱动同一套控制程序，成功 40/40。因此失败可以归因于模型，而不是实验框架。

## 核心发现

**1. 物体位置已知时，能否完成操作？**
在所测的四个抓放任务上，能，而且比较稳定。给出物体真值坐标时，如果模型为固定控制程序选择抓取/放置目标，成功 40/40；如果模型自己直接输出 7 维末端动作，中间不经过任何控制程序，成功 37/40。另外两个抓放任务和一个按旋钮任务上也成立（29/30）。但即使给了坐标，开抽屉（0/20）和推物体（5/10）**仍然不行**。

**2. 撤掉物体坐标后，失败发生在哪里？**
发生在从单个相机判断远近。只看图、直接输出动作时成功 2/40。第一次闭合夹爪时，夹爪沿相机视线方向平均偏 7.2 cm（偏向相机），左右方向只偏 0.3 cm。让它直接说出物体的米制 3D 坐标，成功 0/40。如果它只在图上指像素、由深度图换算成 3D，成功 30/40，因为深度图恰好补上了缺失的那一维。

**3. 增加视角能改善什么，仍然不能解决什么？**
多给一张与主相机垂直的侧视图后，直出动作在四个任务上的成功率从 2/40 升到 34/40，纵深误差从 7.2 cm 降到 1.6 cm。改为提高推理档位，只到 3/16。侧视图解决不了开抽屉（0/18）、推物体（0/9）和按很小的炉子旋钮（4/10）；在容差最严的放置任务上，它常常差 3–4 cm 就宣布完成。

## 能力边界（限于所测任务）

| 能力 | 观察结果 | 依据 |
|---|---|---|
| 已知坐标时选择抓取部位和放置点 | 4 个抓放任务上稳定 | 40/40 |
| 朝已知目标直出 7 维动作（接近、抓取、搬运、放置、按压） | 稳定 | 4 个任务 37/40；另 3 个任务 29/30 |
| 在图上指出物体 | 稳定；但开口在图上的中心与 3D 中心不一致时会出错 | 30/40；碗心任务 1/10 |
| 单个斜视相机下判断远近 | 不行，系统性偏向相机 | 2/40，误差 7.2 cm |
| 两个正交视角下定位 | 基本可以 | 34/40，误差 1.6 cm |
| 从图像直接给出米制 3D 坐标 | 不行 | 0/40 |
| 从侧面接近（抽屉把手） | 不行，给不给坐标都一样 | 0/20、0/18 |
| 非抓取的推 | 不稳定 | 给坐标 5/10 |
| 预见隐含几何关系（夹碗沿时碗心偏移） | 没有提示时想不到；只在容差严时致命 | 9/10 → 2/10 |

适用范围：LIBERO 仿真，10 个 libero_goal 任务，每个条件每个任务 10 回合（高推理档 4 回合），除特别说明外为最低推理档，一种相机布置。尚未与其他模型对比。详见[局限](docs/report_zh.md#局限)。

## 复现

```bash
cd code
export LIBERO_ROOT=/path/to/LIBERO PY=/path/to/venv/bin/python
source env.sh
bash run_condition.sh act_vision_side 1 10     # 条件名、任务号、回合数
$PY analyze.py act_vision_side
```

需要 GPU 节点（MuJoCo EGL 渲染）和已登录的 Codex CLI。每个条件的参数和预期结果列在 [`code/conditions.tsv`](code/conditions.tsv)，环境配置见 [`code/README_zh.md`](code/README_zh.md)。
