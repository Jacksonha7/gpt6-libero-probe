# 通用多模态模型操作机器人时，瓶颈在哪里？

[English](README.md) | **中文**

这是一个在 LIBERO 仿真里做的可复现实验，用来区分通用多模态模型在操作机械臂时能做到什么、做不到什么。当前的研究对象是 GPT-6（`gpt-6-astra`，通过 Codex CLI 调用）；实验框架适用于任何能接收图像、返回结构化文本的模型。

📄 [完整报告](docs/report_zh.md) · 🎬 [全部视频案例](docs/cases_zh.md) · 🛠 [复现](code/README_zh.md) · 📊 [原始成功次数](results/success_rates.csv)

## 研究问题

多模态模型控制机械臂时，限制它的是哪一步：决定做什么、判断东西在空间里的位置，还是生成电机指令？

## 核心结果

四个抓放任务，各 10 回合。每一行里，模型都输出 7 维末端增量动作，直接提交给仿真器自带的末端控制器，不经过任何手写的抓放程序。模型始终能看到主相机、腕部相机和末端位置。

| 模型额外得到的信息 | 成功 |
|---|:-:|
| 物体真值坐标 | **37/40** |
| 无 | **2/40** |
| 一张侧视相机图 | **34/40** |
| 无，但使用高推理档（每任务 4 回合） | 3/16 |

同样两路相机、只看图，只改动作接口：

| 接口 | 成功 |
|---|:-:|
| 直出增量动作（即上表“无”那一行） | 2/40 |
| 绝对末端目标 + 实测位置反馈，每次 ≤5 步 | 3/40 |
| ……再附前 3 次调用的主相机图 | 11/40 |
| 银河通用 GPT-as-Policy 的接口，移植到 LIBERO（任务 8、6） | **8/9** |

## 发现

**1. 物体位置已知时，能否完成操作？**
抓放和按压可以：给出物体真值坐标时，它能规划抓法并输出可用的动作，在 10 个 libero_goal 任务中的 7 个上完成。开抽屉仍然失败，推物体不稳定。

**2. 撤掉物体坐标后，失败发生在哪里？**
在沿主相机视线方向的纵深判断上。在主相机加腕部相机的配置下，夹爪闭合时平均停在物体靠相机一侧 7.2 cm 处，而左右方向的平均偏差不到 1 cm。如果让它只在图上指像素、由深度图换算成 3D，大部分任务能完成；让它直接说出米制坐标，则一个都完成不了。

**3. 增加视角能改善什么，仍然不能解决什么？**
一张与主相机垂直的侧视图消除了大部分纵深误差，提高推理档位做不到这一点。侧视图解决不了开抽屉、推物体、很小的目标，也改不了放置偏了 3–4 cm 就宣布完成的习惯。

**4. 这个纵深失败是模型的上限吗？**
大体不是。相机不变、只换接口，纵深偏差就消失了：改成绝对目标加实测位置反馈后，纵深误差从 7.2 cm 降到 0.5 cm，真正把物体提起来的回合从 6/40 升到 20/40（加历史图 28/40）；把银河通用的整套接口移植到 LIBERO 上，8/9 成功。剩下的失败一半是没降到位就合爪，一半是抓起来了但放错，放错的大多会宣称完成。能否跑代码、推理档位高低都解释不了这个差距。所以各家报告的成功率（0% 到 98%）脱离接口设计是不可比的。

## 能力边界（限于所测任务）

| 能力 | 观察结果 | 依据 |
|---|---|---|
| 已知坐标时选择抓取部位和放置点 | 4 个抓放任务上稳定 | 40/40 |
| 朝已知目标输出增量动作（接近、抓取、搬运、放置、按压） | 稳定 | 4 个任务 37/40；另 3 个任务 29/30 |
| 在图上指出物体 | 稳定；但开口在图上的中心与 3D 中心不一致时会出错 | 30/40；碗心任务 1/10 |
| 主相机 + 腕部相机下判断纵深 | 不行，系统性偏向主相机 | 2/40，误差 7.2 cm |
| 同样相机，绝对目标 + 实测反馈 | 纵深偏差消失（0.5 cm）；但一半回合仍抓不起来（合爪太高），放错时常宣称完成 | 3/40；加历史图 11/40；移植的 GPT-as-Policy 接口 8/9 |
| 加一个正交侧视图后判断纵深 | 基本可以 | 34/40，误差 1.6 cm |
| 从图像直接给出米制 3D 坐标 | 不行 | 0/40 |
| 从侧面接近（抽屉把手） | 不行，给不给坐标都一样 | 0/20、0/20 |
| 非抓取的推 | 不稳定 | 给坐标 5/10 |
| 预见隐含几何关系（夹碗沿时碗心偏移） | 没有提示时想不到；只在容差严时致命 | 9/10 → 2/10 |

适用范围：LIBERO 仿真，10 个 libero_goal 任务，每个条件每个任务 10 回合，除特别说明外为最低推理档，一种相机布置，一个模型。详见[局限](docs/report_zh.md#局限)。

## 复现

```bash
cd code
export LIBERO_ROOT=/path/to/LIBERO PY=/path/to/venv/bin/python
source env.sh
bash run_condition.sh oracle 8 2               # 检查动作原语控制程序，不调用模型
bash run_condition.sh act_vision_side 1 10     # 条件名、任务号、回合数
$PY analyze.py act_vision_side
```

需要 GPU 节点（MuJoCo EGL 渲染）和已登录的 Codex CLI。[`code/conditions.tsv`](code/conditions.tsv) 列出了每个条件的参数和本报告中的成功次数；哪些配置是历史原样、哪些是重建的，见 [`code/README_zh.md`](code/README_zh.md)。
